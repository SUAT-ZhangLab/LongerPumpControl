Windows 两个串口驱动状态 OK。COM3 是 Intel AMT 系统串口，不是本次泵连接。

首先用原 PowerShell 脚本读到响应，发现脚本对 byte 左移 8 位造成高字节丢失，误报 CRC mismatch。将高字节显式转为 int 后，CRC 和寄存器均正确解析。

再用本次软件同源 C# 通信层独立读取状态及当前方案，并分别执行 10 次重复状态读取，全部成功。原始结果见开发目录 build/hardware-results.txt。

初始连接检测仅发送功能码 03。随后用户明确授权实际控制测试，已在两台泵上验证启动（状态 1）、暂停（状态 2）、继续（状态 1）、停止（状态 3），均无故障。运行时间为短时台架测试，沿用原方案；没有修改注射器几何参数或更改现有驱动。

泵先返回写入确认，再异步更新运动状态；软件现已等待回读确认后报告控制结果。

当前参数写入返回 Modbus 异常码 3，尚未解决。厂商驱动中识别了设备使能寄存器 0x0000，测试后恢复 0。COM8 的方案编辑选择寄存器 0x026E 原为 1，改为 2 后能读取有效方案；恢复 1 被固件以异常码 4 拒绝，编辑缓冲区仍指向 2。运行方案、容量、流量、目标液量、驱动力等 0x0060–0x007D 的全部 30 个寄存器保持初始值。

临时诊断程序 FinalStateProbe 曾因未捕获异常退出并显示 Windows 错误对话框，已补异常处理。随后重新读取确认两台泵均停止、故障码 0。这个诊断工具不包含在交付安装包中。
设备响应证明当前串口和协议链路有效；型号和泵序列号随后通过 0x0120–0x013B 独立读取确认。USB 线缆序列号与泵序列号是两种不同标识。
